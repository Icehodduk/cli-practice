# 🌐 엔드투엔드 데이터 파이프라인 & 대시보드 통합 업무 규칙 (Data Pipeline Rules)

본 규칙은 임의의 새로운 웹사이트 및 데이터셋을 대상으로 데이터 수집부터 최종 웹 대시보드 배포까지 전 과정을 일관된 최고 수준의 품질과 안정성으로 완수하기 위한 표준 엔지니어링 지침입니다.

---

## 1. 워크스페이스 구조 및 환경 원칙

1. **폴더 구조 표준화**: 새로운 사이트/프로젝트 작업 시 반드시 프로젝트 디렉터리 내에 다음 4개 하위 폴더를 생성하고 역할을 엄격히 분리하십시오.
   - `data/`: 원본 데이터(`*_raw.json`) 및 정제 데이터셋(`*_cleaned.csv`) 저장
   - `docs/`: 심층 EDA 분석 보고서(`eda_report.md`), 구현 계획서, 태스크보드 보관
   - `images/`: EDA 및 분석 과정에서 생성된 모든 정적 시각화 이미지(PNG) 저장
   - `src/`: 스크래퍼, EDA 분석 스크립트, 대시보드 빌더 등 실행 코드 저장
   - 루트 또는 프로젝트 직하: 독립 실행형 웹앱 대시보드(`dashboard.html`) 배치
2. **가상환경 원칙**:
   - 가상환경은 워크스페이스 루트의 단일 `.venv`만 사용합니다.
   - 새 프로젝트 폴더를 생성하더라도 별도 가상환경을 만들지 않으며, `conda`, `virtualenv`, `python -m venv`의 사용을 일체 금지합니다.
   - 라이브러리 추가는 반드시 `uv add <package>`를 통해서만 수행합니다.
3. **상대경로 원칙**: 특별한 시스템 요구를 제외하고 워크스페이스 내부 파일 참조 및 스크립트 인수는 반드시 상대경로를 사용합니다.

## 2. 웹 스크래핑 및 데이터 수집 철칙

1. **Network API 우선 리버스 엔지니어링 원칙**:
   - 무거운 브라우저 DOM 렌더링에 바로 의존하지 마십시오.
   - 브라우저 개발자 도구 또는 Playwright 네트워크 이벤트(`page.on('response', ...)`)를 통해 대상 사이트의 내부 REST/JSON/GraphQL API 엔드포인트를 먼저 캡처하고 분석하십시오.
   - 내부 API가 발견되면 직접 구조화된 JSON을 고속으로 일괄 수집하고, API 호출이 원천 차단되거나 SSR/정적 렌더링 사이트인 경우에만 Playwright DOM 파싱으로 자동 폴백합니다.
2. **3단계 안티 스크래핑 우회 전략**:
   - **헤더 스푸핑**: 실제 최신 브라우저와 동일한 `User-Agent`, `Sec-CH-UA`, `Accept-Language`, `Referer` 헤더를 반드시 설정하십시오.
   - **요청 지터(Jitter)**: 기계적인 고정 간격 요청을 금지하고, 요청 사이에 $1.5\text{s} \sim 3.5\text{s}$의 랜덤 지연을 부여하십시오.
   - **지수 백오프**: HTTP 429 또는 503 감지 시 $2^n$초 단위로 대기 시간을 늘려 최대 4회까지 재시도하십시오.
3. **데이터 수집 및 정제 분리**:
   - 수집된 원시 데이터는 손실 없이 `data/<project>_raw.json`으로 1차 저장합니다.
   - 결측치 보정, 통화 기호(`₩`, `$`) 및 쉼표 제거, 날짜 표준화(`YYYY-MM-DD`)를 거친 최종 정제 데이터를 `data/<project>_cleaned.csv`로 저장하십시오.

## 3. 심층 탐색적 데이터 분석(EDA) 및 리포팅 철칙

1. **전문 분석가 톤앤매너**: 분석 과정, 코드 설계, 결과 해석 리포트에는 20년차 베테랑 비즈니스 통계 분석가의 품격 있고 통찰력 있는 한국어 어조를 일관되게 유지하십시오.
2. **필수 프로파일링 5단계**:
   - 상하위 5개 행 표본(`head(5)`, `tail(5)`) 마크다운 표 출력
   - `info()` 데이터 타입, 컬럼 목록, 결측치 현황 진단
   - 전체 행 수와 열 수 명시
   - `duplicated().sum()`을 통한 행 중복 검증
   - 수치형 및 범주형 변수 전수 기술통계량 산출
3. **시각화 가이드라인**:
   - **한글 폰트 설정**: `matplotlib` 기반 시각화 시 반드시 `koreanize-matplotlib`를 임포트하여 한글 깨짐을 방지하십시오.
   - **Seaborn 스타일 금지**: `sns.set_theme()`, `sns.set_style()` 등 seaborn 기본 스타일을 사용하지 마십시오. 순수 Matplotlib 스타일 기반으로 깔끔하게 직접 커스터마이징하십시오.
   - **최소 10개 이상의 다각도 차트**: 하나의 EDA 프로젝트 내에서 최소 10개 이상의 그래프(일변량, 이변량, 다변량)를 `images/`에 PNG로 저장하십시오.
   - **표(Table) 동반**: 모든 시각화 차트 아래에는 반드시 대응하는 기술통계표, 교차표(crosstab), 또는 피봇테이블을 마크다운 표 형식으로 함께 제공하십시오.
   - **50자 이상의 해석 가이드**: 모든 그래프마다 도출할 수 있는 비즈니스 인사이트를 서술하는 50자 이상의 구체적인 한국어 해설을 반드시 첨부하십시오.
4. **언어 적응형 텍스트 마이닝**:
   - KoNLPy 등 무거운 형태소 분석기 대신 scikit-learn의 `TfidfVectorizer`를 사용하십시오.
   - 텍스트 표본의 한글/영문 비율을 자동 감지하여 영문 위주 사이트는 영문 표준 불용어, 한글 위주 사이트는 한글 불용어 사전을 적용하여 상위 20~30개 키워드를 추출 및 시각화하고 표를 제공하십시오.
5. **단일 완성형 리포트**: 모든 분석 결과는 `docs/eda_report.md` 단일 마크다운 파일로 체계적으로 완결하십시오.

## 4. Chart.js 기반 인터랙티브 대시보드 구축 철칙

1. **독립 실행형(Standalone) 아키텍처**:
   - 별도의 백엔드 웹 서버 구동 없이도 로컬 파일 탐색기에서 더블 클릭(`file://`)하여 즉시 열 수 있는 단일 HTML 파일(`dashboard.html`)로 구축하십시오.
   - 브라우저 로컬 CORS 제약을 원천 방지하기 위해 정제된 JSON 데이터는 파이썬 빌더를 통해 HTML 내부 `<script>` 변수로 인라인 임베드하십시오.
2. **스타일 및 렌더링 엔진**:
   - 스타일: Tailwind CSS CDN 기반의 깔끔하고 가독성 높은 미니멀 화이트/라이트 테마를 사용하십시오.
   - 차트 엔진: Chart.js v4 CDN을 활용하여 부드러운 반응형 캔버스를 렌더링하십시오.
3. **필수 UI 구성 요소**:
   - **상단 4대 핵심 KPI 카드**: 전체 건수, 대표 수치 평균/중앙값, 최신 항목 비중(%), 1위 테마 키워드를 실시간 동적 계산하여 표출하십시오.
   - **Chart.js 6종 반응형 차트**:
     1. 수치 구간별 분포 막대 차트 (Bar)
     2. 주요 카테고리/발행처 점유율 도넛 차트 (Doughnut)
     3. 시계열/연도별 추이 선 차트 (Line)
     4. 상위 카테고리별 평균 수치 비교 수평 막대 차트 (Horizontal Bar)
     5. 2대 핵심 지표 간 다변량 산점도 (Scatter - 호버 시 상세 정보 툴팁 노출)
     6. TF-IDF 핵심 텍스트 키워드 중요도 차트 (Horizontal Bar)
   - **실시간 다차원 필터 컨트롤 바**: 검색창(디바운스), 카테고리 드롭다운, 수치 구간 드롭다운, 기간 드롭다운, 초기화 버튼을 제공하고, 필터 변경 시 모든 차트와 KPI 카드, 테이블이 즉시 리렌더링되어야 합니다.
   - **상세 데이터 테이블 & CSV 익스포트**: 정렬(오름/내림차순), 페이지네이션(10/25/50건), 엑셀 한글 호환을 위한 `UTF-8 with BOM` 인코딩 기반의 CSV 다운로드 버튼을 반드시 내장하십시오.
4. **대용량 2-Tier 최적화**:
   - 데이터 포인트가 1,000건을 초과하는 대규모 데이터셋의 경우 산점도는 최대 1,000개 대표 표본을 샘플링하여 렌더링 렉을 방지하십시오.

## 5. 장애 복구력 및 품질 검증 철칙

1. **파일 기반 체크포인트 운영**:
   - 각 Phase 완료 시 `data/.checkpoint_phase1.json`, `docs/.checkpoint_phase2.json`, `.checkpoint_phase3.json` 플래그를 생성하여, 파이프라인 재실행 시 완료된 단계를 자동으로 건너뛰고 실패한 단계부터 즉시 재개하십시오.
2. **사후 자동 검증**:
   - 대시보드 생성 후 반드시 HTML 구문, 6개 차트 캔버스 존재 여부, 인라인 데이터 전수 건수 일치 여부를 자동화 스크립트로 검증하십시오.
